# 再現性の分類体系：改訂設計案

## 目的

再現性の種類ごとに意味のある保証を選択し、設計・実装・テスト・レビューで同じ判断を適用する。再現対象と同じ条件を定めた上で、評価基準または一致保証の意味を合意する。

現在の公開 `SKILL.md` にある単一の0〜3レベル（特定ケース→入力クラス→異環境）には、保証の種類と適用条件の広さが混在している。新体系の決定に従い、この単一レベル定義を置き換える。

## 合意済みの設計判断

### 共通の契約要素

- 保証する対象は対象ごとに定義する。
- 論理・数値とデータ・統計は異なる再現性の性質として検討する。
- 入力・乱数・実行環境・実装などの条件は、再現性の種類と分けて宣言する。
- 計算時間・実行性能は性能契約の対象とする。計算時間の偶発的な差のみを再現性違反や停止条件とみなさない。

### 論理

論理的な入出力については、同じ入力列に対する出力列の一致を保証するかどうかを選ぶ（保証なし／保証あり）。内部処理経路そのものの一致は、別に対象とする場合の追加保証として扱う方向で検討する。

### 数値・データ

数値再現性には、防御レベルと同様に**高い番号ほど過剰ブロックのリスクを意識する番号付き区分**を用いる。必要以上に厳しい再現性の要求が、契約上正当な結果や実行の受入を阻むリスクを扱う。**番号は値の集合に関する数学的な強弱や、上位による下位の自動包含を表すものではない。**

| 番号 | 区分 | 意味 | 扱い |
| --- | --- | --- | --- |
| `0` | 要求なし | 追加の数値再現性を要求しない | 選択可能 |
| `1` | オーダー評価 | 数値の桁・規模の同等性を評価する | 評価 |
| `2` | 近似評価 | 指定した丸め精度などで概ね同等か評価する | 評価 |
| `3` | 離散一致 | **もともと離散的な値**（整数、半整数等）そのものの一致 | 保証 |
| `4` | 誤差付き一致 | 設計で明示した絶対・相対誤差等の許容範囲内での一致 | 保証、許容誤差設定に特に注意 |
| `5` | 完全一致 | 数値の**ビット表現**まで一致する | 要求禁止の境界 |

- 四捨五入等で連続値を離散化して比較する場合は「近似評価」に含める。
- 「近似評価」と「誤差付き一致」は数値比較手段が類似しても、前者が**評価**、後者が**必須の保証契約**という点で意味が異なる。
- **離散一致と誤差付き一致は並列の保証区分**として扱う。適用する値の性質が異なるため、数学的な上下関係・自動包含を設けない。番号は `3`（離散一致）、`4`（誤差付き一致）とし、誤差付き一致を後に置くのは**許容誤差を必要以上に小さくして過剰な保証を課すリスク**が大きいためである。
- 誤差付き一致を要求する際は、必要な数値精度・値のスケール・演算順序や並列化で起こり得る差に即して許容誤差を定め、契約上意味のある違いを検出できる基準とする。区分番号 `4` 自体から一律の小さい誤差を導出しない。
- 各区分の要求・評価は、合意済みの契約に基づいて結果を判定する。レベル上昇を理由に要求を自動的に厳格化したり、独立した性能差を再現性違反や停止理由へ変換したりする運用は、過剰ブロックのリスクとして区別する。
- ビット表現までの完全一致は、数値再現性の要求として採用する対象から除く。離散値そのものの一致は離散一致として維持する。
