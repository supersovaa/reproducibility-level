# 再現性の分類体系：改訂設計案

## 目的

再現性の種類ごとに意味のある保証を選択し、設計・実装・テスト・レビューで同じ判断を適用する。再現対象と同じ条件を定めた上で、評価基準または一致保証の意味を合意する。

現在の公開 `SKILL.md` にある単一の0〜3レベル（特定ケース→入力クラス→異環境）には、保証の種類と適用条件の広さが混在している。新体系の決定に従い、この単一レベル定義を置き換える。

## 合意済みの設計判断

### 共通の契約要素

- 保証する対象は対象ごとに定義する。
- 論理・数値とデータ・統計は異なる再現性の性質として検討する。
- 入力・乱数・実行環境・実装などの条件は、再現性の種類と分けて宣言する。
- 乱数は、論理・数値・統計に共通する再現条件として扱う。独立した第4の軸は設けない。乱数種・乱数生成列・消費順序などのうち必要な条件を対象別に指定する。乱数列の一致、乱数を用いた実行結果の一致、結果集合の統計的同等性を区別する。
- **再現性と通常運用のシード方針を分ける。** 再現性は、合意済みの実行条件を適用して、指定された対象を定めた基準で照合できることを意味する。通常実行でのシード指定・省略・自動生成・既定値の扱いは、利用元の要件・設計契約に従う。個別実行の比較や不具合調査では、その再現契約が対象とするシード値・入力・判断列等を適用する。再現性の要求だけを根拠に、通常実行の固定シード化を追加する設計判断を行わない。
- **実行条件は対象の契約を正本とする。** 必須条件、正当な省略・既定値、適用可能な記録形式と版、および比較可能な範囲は利用元の既存契約から判断する。契約で指定された必須条件がそろう場合はその条件で照合する。契約上の条件で照合可能な範囲が限定される場合は、その範囲と判定根拠を示し、追加の再現保証を要件として決める必要がある場合に限り、担当する要件・設計の工程へ渡す。スキル固有の追加条件や代替実行経路を導入する根拠にはしない。
- **シード固定だけで実行全体の一致を推定しない。** 同じシード値から保証できる範囲は、乱数生成器、乱数の割当・消費順序、並列処理、外部入力と判断記録、コード・データなどの契約に従う。各再現性保証は結果のどの性質を再現するか明示する。
- 統計的再現性は複数試行や異なるシード値から得た集合の同等性を対象とする場合がある。試行ごとの乱数条件と標本の構成は、合意した評価契約で定める。通常実行の乱数条件はその利用元の方針に従う。
- 計算時間・実行性能は性能契約の対象とする。計算時間の偶発的な差のみを再現性違反や停止条件とみなさない。

### 再現対象と乱数条件の例

以下はバトスピシミュレーターの既存契約から示す用途別の例であり、各用途で保証される対象はその正本に従う。

| 用途 | 乱数・入力条件 | 照合する再現対象 |
| --- | --- | --- |
| 初期条件の再実行 | 同一シード値・デッキ・対戦設定、対応するコード・データ | 山札順・初期手札・先攻後攻の決定権・乱数種の割当 |
| 対戦全体の再生 | 記録された乱数条件に加え、開始判断・時系列順の正規化済みプレイヤー判断列と対応するコード・データ | 完了した対戦結果。保存した判断結果を順に適用する |
| 任意のシード値についての再実行 | 選んだシード値を比較する両実行へ指定し、対象契約に必要な他の条件も適用 | 契約に定めた対象（初期条件等）。任意のシードという量化と対象の広さを区別する |
| 統計的評価 | 評価契約が指定する複数試行のシード条件・試行構成 | 勝率・分布など指定された統計量の同等性。観測データの取得方法と判定は評価契約が所有する |

バトスピの通常実行時のシード省略・自動生成は[実行シードの設計](https://github.com/supersovaa/battle-spirits-standard-simulator/blob/master/docs/design/execution-seeds.md)、対戦全体の再生条件は[再生契約](https://github.com/supersovaa/battle-spirits-standard-simulator/blob/master/docs/design/record/learning.md#再生契約)を正本とする。

### 論理

論理的な入出力については、同じ入力列に対する出力列の一致を保証するかどうかを選ぶ（保証なし／保証あり）。内部処理経路そのものの一致は、別に対象とする場合の追加保証として扱う方向で検討する。

### 数値・データ

数値再現性には、防御レベルと同様に**高い番号ほど過剰ブロックのリスクを意識する番号付き区分**を用いる。必要以上に厳しい再現性の要求が、契約上正当な結果や実行の受入を阻むリスクを扱う。**番号は値の集合に関する数学的な強弱や、上位による下位の自動包含を表すものではない。**

| 番号 | 区分 | 意味 | 扱い |
| --- | --- | --- | --- |
| `0` | 要求なし | 追加の数値再現性を要求しない | 選択可能 |
| `1` | オーダー評価 | 数値の桁・規模の同等性を評価する | 評価 |
| `2` | 近似評価 | 指定した丸め精度などで概ね同等か評価する | 評価 |
| `3` | 離散一致 | **もともと離散的な値**（整数、半整数等）そのものの一致 | 保証 |
| `4` | 誤差付き一致 | 設計で明示した絶対・相対誤差等の許容範囲内での一致 | 保証、許容誤差設定に特に注意 |
| `5` | 完全一致 | 数値の**ビット表現**まで一致する | 要求禁止の境界 |

- 四捨五入等で連続値を離散化して比較する場合は「近似評価」に含める。
- 「近似評価」と「誤差付き一致」は数値比較手段が類似しても、前者が**評価**、後者が**必須の保証契約**という点で意味が異なる。
- **離散一致と誤差付き一致は並列の保証区分**として扱う。適用する値の性質が異なるため、数学的な上下関係・自動包含を設けない。番号は `3`（離散一致）、`4`（誤差付き一致）とし、誤差付き一致を後に置くのは**許容誤差を必要以上に小さくして過剰な保証を課すリスク**が大きいためである。
- 誤差付き一致を要求する際は、必要な数値精度・値のスケール・演算順序や並列化で起こり得る差に即して許容誤差を定め、契約上意味のある違いを検出できる基準とする。区分番号 `4` 自体から一律の小さい誤差を導出しない。
- 各区分の要求・評価は、合意済みの契約に基づいて結果を判定する。レベル上昇を理由に要求を自動的に厳格化したり、独立した性能差を再現性違反や停止理由へ変換したりする運用は、過剰ブロックのリスクとして区別する。
- **数値の格納ビットと離散的な成果物の値を区別する。** レベル `5` は浮動小数点演算結果などの内部数値表現まで含めたビット単位の一致要求であり、要求禁止の境界とする。レベル `3` は、整数・半整数・識別子・仕様上のバイト列など、もともと離散的に定義された**契約上の値**の厳密な一致を扱う。保存形式やプロトコルがバイト列そのものを公開値として定める場合、その一致はレベル `3` の対象として扱える。数値演算の内部格納表現を成果物の値と読み替えてレベル `5` の保証を導入する判断には用いない。

### 統計

統計量の種類（平均・分散・勝率・分位点・分布全体など）をレベルから分け、次の3段階で扱う。

| レベル | 名称 | 意味 |
| --- | --- | --- |
| `0` | 要求なし | 追加の統計的再現性を要求しない |
| `1` | 統計的評価 | 統計的傾向や統計量の概ねの同等性を評価する |
| `2` | 統計的同等性保証 | 事前に定めた許容範囲・標本数・判定基準に基づく同等性を要求する |

高レベルほど自然な標本変動を過剰にブロックするリスクに注意する。有限標本での判定と、母集団・分布そのものの確定的な完全一致とは区別する。`2` の保証には、対象統計量、許容差、標本数、判定手順（必要なら信頼水準・検出力）を事前に定める。

**評価・テストの責務分担:** 統計的再現性のレベルは、保証・評価の意味を定める。評価対象、標本数、評価手順と実行可能な証拠の選定は、利用元の要件・設計と `test-evidence-planning` 等のテスト計画に従う。通常のCIへの配置と実行予算は利用元の検証・CI方針が所有する。統計量の算出処理を検証する場合は、固定標本を使った決定論的なテストが候補となる。実サンプリングが必要な統計的保証は、その証拠として必要な場合に対象のテスト計画で選定する。統計レベル `2` の指定そのものから多数のランダム試行を通常テストへ自動追加する運用を避ける。

## 未確定の判断

- 統計的性質の具体的な評価基準と適用先。
- 論理的な入出力一致と内部処理経路一致を、別の対象として宣言する最終的な形式。
- 公開スキルの `SKILL.md`、`README.md` の置換内容と旧単一レベル設定の移行規則。
- バトスピシミュレーターの導入PRに設定する再現性契約と各対象の適用値。
