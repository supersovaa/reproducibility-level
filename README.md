# Reproducibility Level

A lightweight skill for a single user and an AI agent to agree on and apply **target-specific reproducibility contracts** during design, implementation, testing, and review.

The operational rules and level definitions live in [SKILL.md](SKILL.md). The [classification design](docs/reproducibility-framework.md) records the reasoning behind the three-axis framework.

## Select the reproducibility needed

For each target, use the owning requirements and design to specify its **target, conditions, equivalence criterion, and relevant axes/levels**.

| Axis | Levels | Meaning |
| --- | --- | --- |
| Logical | `0`, `1`, `2` | No additional guarantee; agreed input/output equality; input/output plus expressly contracted internal processing-path equality |
| Numerical/data | `0`–`5` | No additional requirement; magnitude assessment; approximate assessment; exact agreement of originally discrete values; toleranced agreement; prohibited internal numeric-bit-identity boundary |
| Statistical | `0`, `1`, `2` | No additional guarantee; statistical assessment; contracted statistical equivalence |

Specify **only the axes relevant to each target**. A deliberately selected `0` preserves the existing behavior contract. Numeric/data `3` and `4` are parallel forms of guarantees, not automatically nested. Higher numbers call for greater attention to overconstraint risk, rather than automatically strengthening all earlier criteria.

Inputs, RNG/seed conditions, code and data versions, and environment differences belong to each target's **conditions**, not to separate reproducibility levels. Follow the consuming system's normal seed policy, including its specified and autogenerated seed behavior. A seed that reproduces initial conditions does not by itself guarantee the later decision sequence or outcome.

### Example

A game simulation may declare these *separate* targets under its own existing contracts:

```text
Target: initial card arrangement
  Conditions: same selected seed, decks, setup, and corresponding code/data
  Equivalence: same contract-defined discrete arrangement
  Numerical/data: 3

Target: replay of recorded decisions
  Conditions: recorded initial settings, RNG information, decisions, code/data
  Equivalence: all recorded decisions consumed; contracted result matches
  Logical: 1

Target: numerical values in a learning run
  Conditions: the learning operation's existing contract
  Numerical/data: 0 (no additional numerical reproduction guarantee)
```

The illustration assigns levels to *declared targets*; it does not impose an execution mode, fixed default seed, exact floating-point bit pattern, or new test workload.

## Timing, performance, and testing

Reproduction of a contracted result is separate from elapsed-time or throughput guarantees. Existing performance requirements and test-execution budgets govern those limits.

Test-evidence planning owns the choice of tests, workloads, statistical sample sizes, and CI placement. Statistical level `2` does not automatically entail thousands of trials in routine CI.

## Installation and migration

Install the root [SKILL.md](SKILL.md) in your agent's skill directory, such as `<skills-root>/reproducibility-level/SKILL.md`, and reference it from the work types that establish or apply reproduction contracts.

For existing users of the former single `0`–`3` system, examine each authoritative target, conditions, and equivalence requirement, then select the appropriate axes and levels. Old numbers have no automatic new-number mapping. Retain the existing system's agreed guarantees during the transition.

## Responsibilities

This skill interprets reproducibility guarantees. [defense-level](https://github.com/supersovaa/defense-level) handles defensive scope; [requirement-driven-testing](https://github.com/supersovaa/requirement-driven-testing) handles executable evidence; performance and operational requirements govern timing and resource limits.
